# Adding a city to Never Roam Alone

This site keeps city data in about ten separate files (the detail page, homepage map, city directory, destination finder, sitemap, transit popups, day trips, season pills, curated scores, and the link-preview edge function). A new city needs to land in all of them, or it quietly falls out of sync — see `_guidebuild/CITY_SCHEMA.md` and the project memory `add_city_tool.md` / `city_count_247_verified.md` for the full story of how that happened once already (Jeddah).

The fix is a two-phase process: **research** the city into one JSON record, then **run `_guidebuild/add_city.py`** on it, which splices that record into every file at once and reports exactly what it added vs. what still needs attention.

## Before starting

If the city name is ambiguous (there's more than one real place with that name, e.g. "Springfield" or "Valencia" could mean more than one country) or the user hasn't said which country, ask before doing any research — cheap to clarify up front, expensive to research the wrong city.

Check whether the city is already live: search `city.html` for `city:"Name"` or `"city":"Name"`. If it's already there, tell the user and ask if they meant something else (a refresh of existing data, a different city) rather than silently re-adding.

## Phase 1: Research

Read `_guidebuild/CITY_SCHEMA.md` for the full field list — it's the single source of truth for exactly what's required, what's optional, and what must NOT be hand-filled (temps/rain-derived season data and the tagline-derived link-preview entry are auto-generated by the script, don't research those separately). `_guidebuild/example-city.json` is a real filled-out record to use as your template shape.

Research every **required** field with real facts — use WebSearch/WebFetch, not invented numbers. For the handful of fields that are best copied from a similar existing city's shape (`transit`, `transport`, `airport`, `net`), open a comparable real entry in `city.html` (same region, similar size) and match its structure, then fill in facts specific to the new city.

For the **optional** sections (`routes`, `daytrips`, `score`), include them if you can find real content worth adding, but it's fine to omit any of them — the script will flag what's missing rather than fail, and the user can fill those in later. Never fabricate a transit route, a day-trip attraction, or a score number; skip the section instead.

Assemble one JSON file per batch of cities (a single object, or a list of objects for multiple cities at once) matching the schema exactly — field names and types matter, `add_city.py` won't guess.

## Phase 2: Install

Run the script from the project root (or set `GUIDE_ROOT` to the project folder):

```
python3 _guidebuild/add_city.py newcity.json
```

It's safe to re-run — already-present entries are skipped, not duplicated. Read its report carefully: `added` confirms what worked, `skipped/needs-followup` tells you exactly what still needs a human (a missing photo, an optional section you left out). Relay that report to the user plainly — don't just say "done," say what's done and what's still open.

## Phase 3: Verify

Before telling the user it's finished:
- Run `_guidebuild/checkjs.py` against `city.html`, `index.html`, and `cities.html` (checks every inline `<script>` for syntax errors).
- Run `node --check` on the plain `.js` files the script touched (`destinations.js`, `city-seasons.js`, `city-routes.js`, `day-trips.js`, `city-scores.js`, `netlify/edge-functions/city-meta.js`).
- Parse `sitemap.xml` to confirm it's still valid XML (e.g. `python3 -c "import xml.dom.minidom; xml.dom.minidom.parse('sitemap.xml')"`).

If working through the device bridge (Cowork), stage the files, run the script and checks in the sandboxed copies exactly as done for the Jeddah/247-city fix, then `device_commit_files` the results back — don't run the script directly against files you haven't staged into a workspace you control.

## After it's done

Tell the user plainly:
- Which fields/files got real data vs. which optional sections were skipped (and why — missing research, not a bug).
- That a real photo still needs to be dropped at `images/cities/<slug>.jpg` if the report flagged it missing — nothing sources one automatically.
- That, like every other change to this site, it needs `git push` + a Netlify redeploy to go live — nothing here deploys itself.

No i18n/translation follow-up is needed — the site's long-form city content translates live via API for every city automatically (see `city_count_247_verified.md`).
